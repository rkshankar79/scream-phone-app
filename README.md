# SPA - SCReAM Phone App

![Platform](https://img.shields.io/badge/platform-Android-green)
![Language](https://img.shields.io/badge/Kotlin-C++-blue)
![Status](https://img.shields.io/badge/status-Alpha-orange)

Android implementation of the SCReAM congestion control algorithm from Ericsson Research.

SPA is a real-time **network testing and visualization tool**: it runs Ericsson's
SCReAM engine on Android, generates synthetic RTP/UDP test traffic, exchanges
RFC 8888 RTCP feedback, and visualizes the congestion-control state live. It is a
measurement tool for SCReAM and future **L4S** evaluation — **not** a video
streaming app.

> Upstream algorithm: [EricssonResearch/scream](https://github.com/EricssonResearch/scream).
> The core C++ engine is vendored **untouched** under `app/src/main/cpp/scream_core/`.

---

## Features

- **Sender mode** — synthetic RTP/UDP traffic with SCReAM pacing and congestion control.
- **Receiver mode** — RFC 8888 standardized feedback generation.
- **On-device loopback** — sender ↔ receiver in one app, no external server needed.
- **Live dashboard** — CWND, RTT, TX/target/pacing bitrate, queue delay, packet loss
  (custom dependency-free Jetpack Compose charts).
- **CSV export** — full per-sample session log via the Android file picker.
- **ECN-ready** — ECT codepoint configurable on transmit (full L4S/CE reception planned).

## Metrics

| Metric | Source (core API) |
|---|---|
| Congestion window (CWND) | `getCwnd()` |
| RTT (smoothed) | `getSRtt()` |
| TX / target / pacing bitrate | `getStatisticsItem` / `getTargetBitrate()` |
| Queue delay | `getStatisticsItem(AVG_QUEUE_DELAY)` |
| Packet loss | `getStatisticsItem(LOSS_RATE)` |
| Feedback count / packets sent | session counters |

CSV columns: `timestamp_ms, rtt_ms, cwnd_bytes, target_kbps, tx_kbps, pacing_kbps,
queue_delay_ms, loss_pct, feedback_count, packets_sent`.

## Architecture

Layered so the vendored Ericsson code stays pristine and the transport/JNI layer
never depends on a concrete engine:

```
Kotlin / Compose UI ─▶ ScreamService (foreground + wakelock)
        └─ ScreamEngine (StateFlow, poll loop) ─▶ ScreamBridge (JNI)
══════════════════════ JNI boundary ══════════════════════════════
   wrapper/      TestSession (sender), ReceiverSession (receiver), *_jni.cpp
   controllers/  ScreamController, ScreamReceiver   (adapters — only code that
   interfaces/   CongestionController, FeedbackReceiver, MetricsSnapshot   includes core)
   scream_core/  ScreamV2Tx / ScreamRx / RtpQueue   (UNTOUCHED Ericsson code)
```

- `scream_core/` — never edited; vendored upstream. Metrics come from its public API.
- `interfaces/` — pure abstract contracts + POD structs.
- `controllers/` — concrete adapters; the only TUs that include `scream_core/`.
- `wrapper/` — sockets, threads, JNI; depends on `interfaces/`, never on the core directly.

See [`PROJECT.md`](PROJECT.md) for the full design, data flow, and JNI surface.

## Build

Requires Android Studio with:
- Android SDK Platform **34**
- **NDK** (side-by-side) + **CMake 3.22.1**
- ABIs: `arm64-v8a` (device), `x86_64` (emulator)

Open the project in Android Studio, run a Gradle Sync (generates `local.properties`
and the Gradle wrapper), then Run ▶. Package id: `com.spa.scream`.

> Note: the Gradle wrapper JAR/scripts are generated by Android Studio on first sync
> and are not committed. Command-line `./gradlew` builds require running `gradle wrapper` once.

## On-device loopback test

1. **Receiver** card → Listen port `30000` → **Start RX**.
2. **Sender** card → Server IP `127.0.0.1`, Port `30000`, Local port `0` → **Start**.
3. Receiver RTP/feedback counters climb; sender shows feedback > 0, CWND ramps, and
   live RTT/queue-delay. (Start the receiver before the sender.)

Use a valid IP (e.g. `127.0.0.1`) — invalid addresses now fail loudly.
